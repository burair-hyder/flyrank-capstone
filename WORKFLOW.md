# Workflow comparison: vague vs. precise AI-assisted implementation

I compared the two implementations in the ai-vague-feature and ai-precise-feature branches. The vague-prompt branch produced a broader settings experience with fields for display name, email, bio, password changes, theme, language, and email notifications. The precise-prompt branch implemented a narrower form around name, email, email notifications, and theme, and it also added a dedicated validator plus Vitest tests. The main difference was not just scope, but the level of specification: the vague approach asked the model to infer behavior from a general request, while the precise approach forced the AI to work from explicit acceptance criteria.

The precise branch was stronger on correctness because the behavior was easier to define and verify. In the validator, it trimmed the name, required a non-empty value, validated email format, and exposed an explicit isSettingsFormValid helper. The vague branch also handled more rules, including password-strength checks, password confirmation, bio length, and multiple form fields, but that broader surface area made it easier for subtle issues to hide. The test file in the precise branch made the intended behavior concrete: it covered empty and whitespace-only names, invalid and valid email addresses, and the happy-path validation flow.

Accessibility was also easier to reason about in the precise branch. Both implementations used labeled form controls and error text, but the precise branch kept the form smaller and more straightforward, which made it simpler to audit whether each control had the right label, error association, and alert behavior. The vague branch had more moving parts and a richer component structure, so reviewing accessibility and state handling took more effort.

The edge-case handling was another clear difference. The precise branch explicitly tested whitespace-only names and invalid email formats, while the vague branch had a more complex validation flow that covered password-related edge cases but lacked a comparable test scaffold. One mistake that stood out during review was the need to treat whitespace-only values as invalid input; the added tests made that edge case explicit rather than implicit. The lesson from both branches is that AI-assisted development is most effective when the prompt is specific, the acceptance criteria are concrete, and tests are written alongside the implementation.
